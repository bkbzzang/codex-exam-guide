# Ponytail - Minimal Implementation & Cost Engineering

## 핵심 원칙

요구사항을 충족하는 가장 단순하고 안정적인 방법을 우선한다.

### 1. 구현 전 검토
- 과제 요구사항과 기존 코드 구조를 먼저 확인한다.
- 재사용 가능한 기능이나 코드가 있는지 검토한다.
- 요구사항에 없는 기능은 임의로 추가하지 않는다.

### 2. 최소 구현
- 브라우저 기본 기능과 표준 라이브러리를 우선 활용한다.
- 기존 설치된 라이브러리를 우선 사용하고, 새 패키지는 꼭 필요한 경우에만 추가한다.
- 불필요한 추상화, 중복 코드, 추가 파일 생성을 피한다.

### 3. 비용 및 시간 관리
- 과도한 분석과 불필요한 코드 재작성을 피한다.
- 한 번에 처리할 수 있는 작업은 효율적으로 묶어서 진행한다.
- 정상 작동하는 코드는 불필요하게 변경하지 않고, 문제와 관련된 부분만 수정한다.

### 4. 품질 유지
- 코드 최소화보다 요구사항 충족과 안정성을 우선한다.
- 필수 기능, 입력 검증, 예외 처리 및 보안을 생략하지 않는다.
- 구현 후 핵심 기능을 검증하고, 확인하지 않은 항목은 성공했다고 보고하지 않는다.

## 최종 판단 기준

1. 이 기능이 과제에 정말 필요한가?
2. 기존 코드나 기능으로 해결할 수 있는가?
3. 더 단순하고 안정적인 방법이 있는가?
4. 이 변경이 결과물의 품질을 실제로 높이는가?

불필요한 작업은 하지 않되, 필요한 작업은 충분히 수행한다.
